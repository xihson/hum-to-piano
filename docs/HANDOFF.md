## 2. 任务清单（建议按顺序做）

内部数据**继续用 `'clap'` 和 `'snap'`** 表示军鼓和踩镲（`hits[].k`、`song.mute` 的键、事件 `lane`），只改显示文字，避免迁移旧数据。播放时 `clap` 用 `snare` 音色，`snap` 用 `hat` 音色，和现在一样。

### T1 录音只识别哼唱；按键打鼓

现状：`analyzeTake()` 调用 `DSP.detectHits()` 从录音里找拍手和响指，`liveHits()` 做实时检测。

要做：
1. 删除拍打声检测：`app.js` 的 `liveHits`、`makeHP`、`R.hp2/hp5/hf/lastHit`；`analyzeTake` 里的 `detectHits`、`mask`、“把音符起点移回拍手”那段；`dsp.js` 的 `detectHits`、`classify`，以及只被它们用到的 `centroid`、`fft`、`highpass`（删之前用 Grep 确认没有别处在用）。`DSP.transcribe(frames)` 不再传 mask。
2. 录音时的按键（只在录音页、或添加段落弹窗正在录音时生效）：
   - **空格** → 军鼓（`'clap'`）；**Alt**（AltLeft、AltRight）→ 踩镲（`'snap'`）。忽略 `e.repeat`。Alt 的 keydown 和 keyup 都要 `preventDefault()`，否则 Windows 上的 Firefox 会把焦点移到菜单栏。
   - **回车** → 停止并分析（和红色停止按钮一样）。**Esc** → 放弃这次录音，回到首页（添加段落弹窗里 = 停止录音、不分析）。
   - 预备拍期间按的键忽略，不显示。
3. 每次打击：
   - 立刻用 `Synth.play(R.S, R.bus, { drum: 'snare' | 'hat', t: c.currentTime, v: .8 })` 发声；
   - 往 `R.live.hits` 推 `{ t: c.currentTime - R.firstCtx, k }`，实时画面在“现在”线上画点（`drawLive` 已经会画）；
   - 记下 `{ ctx: c.currentTime, k }` 到 `R.taps`。
4. 时间换算（`stopCapture` 里算好，传给 `analyzeTake`）：
   - **开节拍器**：用户是跟着听到的咔嗒声按键，而声音从扬声器出来晚了 `outLat = c.outputLatency || c.baseLatency || 0`。所以这一下的拍子位置 = `(tap.ctx - outLat - R.beat0Ctx) / R.spb`。这里**不用**节拍器回声校准值；那个值只用于麦克风收到的人声。
   - **不开节拍器**：换成录音缓冲区里的秒数 `tap.ctx - R.firstCtx`，和音符起点一起交给 `DSP.estimateTempo`，再用 `DSP.toBeats` 量化。这样可能差几十毫秒，16 分音符量化能吸收大部分，已知限制，写进 ARCHITECTURE。
   - 建议的新签名：`analyzeTake(buffer, info, taps)`。`taps` 是 `[{ t: 秒（缓冲区时间）, k }]`，或者开节拍器时直接给拍子 `[{ b: 拍, k }]`，二选一，写清楚即可。`toBeats` 里的 hits 参数改成接受 `{ t, k }`（现在读的是 `h.kind`）。
5. 只录到鼓点、没有哼唱，也要生成作品（只有军鼓 / 踩镲轨道）；两者都没有才算失败。
6. 文案：`没有听出旋律或拍手。…` 改成 `没有听出旋律。离麦克风近一点再试。`（上传时是 `没有听出旋律。换一段更清楚的录音试试。`）。上传文件只分析哼唱。
7. 更新 `window.__app`：暴露新的 `analyzeTake`，方便测试按键换算。

验收：合成录音（`v2/dev/fixture.js`）载入后旋律正确，没有任何自动检测出的鼓点；在控制台用 `__app.analyzeTake(buf, info, taps)` 传入人工打击时，鼓点落在预期的 16 分音符上。

   - `bassNote(name, base)` 用 `bass`。
3. `arrange.js`：
   - `seventh(name, key)` 要先拆掉斜线，加完七音再接回去。
   - `bassEvents` 里 `r = Theory.bassNote(name)`（斜线音）；`fifth` 用和弦根音的五度，放在 `r` 附近的音区。
   - `power8` 用斜线音。
   - `harmonize` 和 `reharmonize` 的结果不带斜线：改调或重新配和弦后，低音选择会被重置，这是预期行为，写进 UX 文档。
4. 和弦编辑（`buildChordPicker`）加第三排：左边小字 `低音`，后面是这个和弦的组成音：
   - 三和弦是三个按钮，名字用 `Theory.pcName(pc, song.key)`，下面小字分别是 `根音`、`三音`、`五音`；
   - 七和弦和挂留和弦只显示音名，不显示小字。
   当前选中的低音高亮（`--chords` 底）。点根音 = 去掉斜线，点其他音 = 设为 `和弦/音名`；走 `commit`，并试听和弦加低音。第一、二排选新和弦时，低音重置为根音。第一、二排高亮时，用去掉斜线后的和弦名比较。
5. 编排区的和弦块显示完整名字（`F/A`）。MIDI、WAV、Suno 提示词不用特别处理。

### T12 手机横屏（Figma 25、M1、M1b、M2、M3、M4）

1. 判断手机：`matchMedia('(pointer: coarse)').matches && Math.min(screen.width, screen.height) < 600`。
2. 竖屏录完（分析成功、进入作品页时）在手机上显示 `#rotateOverlay`（M1）：
   - 旋转图示（虚线竖手机 + 蓝色横手机 + 弯箭头，SVG 照 Figma M1）；
   - 标题 `横过来编辑`；
   - 下面小字链接 `先不用`，点了关掉提示，留在竖屏。
   转成横屏（`matchMedia('(orientation: landscape)')` 的 change）时自动消失。5 秒内没转过来，弹出 toast `尝试关闭旋转锁定。`（M1b，文案进 T13 的文案表）。每次录完最多提示一次。
3. **不用** Fullscreen API，**不锁定方向**（用户实测往下滑两下浏览器栏就收起了）。高度用 `100dvh`。
4. 横屏手机布局（`@media (orientation: landscape) and (max-height: 500px)`）：

5. 竖屏手机的作品页：保持现在的竖排布局，能用就行；不需要新设计。

## 3. 容易踩的坑

- `L.bw` 改成有最小值以后，`renderArr` 里所有用 `scroll.clientWidth` 的地方要检查一遍。`#arrScroll` 的 `scrollLeft` 在每次 `renderArr` 重建 DOM 后要保住（现在会被重置吗？先测）。
- `gesture()` 的 5px 阈值用在鼠标上；触摸的长按要另写计时器，并在 `pointermove` 超过 5px 时取消。`.sec` 现在是 `touch-action: none`，平移要自己实现。
- 空格在作品页是播放 / 暂停，在首页是开始录音，在录音页是军鼓；焦点在按钮上时，现在的代码会跳过空格。录音页里停止按钮有焦点时，空格也必须是军鼓，不能触发按钮点击：在 keydown 里 `preventDefault()`，并且在 keyup 时也拦截。
- Alt 在 Mac 上是 Option 键，`e.code` 是 `AltLeft` / `AltRight`，行为一样。
- 预备拍阶段 1 把内容设成 `opacity: 0`，同时要设 `pointer-events: none`。
- 开发用的浏览器面板没有麦克风。录音相关的界面可以用一个假的 `R` 或在控制台调用内部函数来看，按键换算用 `__app.analyzeTake` 测。
